## Phase 1 Scope

Phase 1 performs a **dataset audit only**. It does NOT:

- Download or extract audio archives
- Decode, segment, or process audio files
- Extract ecoacoustic indices, YAMNet embeddings, or SurfPerch embeddings
- Train classifiers or generate performance metrics

Phase 2 (feature extraction and modelling) requires explicit researcher approval after reviewing this audit.

- Python 3.9 or later (standard library only — no external packages required for Phase 1)

## How to Run the Audit Script

```bash
# From the project root
cd EcoSound-Audit

# Run the audit (Python stdlib only — no pip install needed)
python scripts/audit_dataset.py
```

The script:
1. Fetches the Figshare API metadata for article 29958062.
2. Downloads `manifest.csv` (5 KB) from Figshare and caches it locally.
3. Runs 10 audit checks (A through J).
4. Writes `reports/audit_summary.json` and `logs/audit.log`.

Expected runtime: **30–120 seconds** (network dependent).

## Phase 1 Key Findings (Summary)

- **5 countries verified:** Australia, Indonesia, Kenya, Maldives, Mexico
- **45 sites verified:** 7 (AUS), 21 (IND), 5 (KEN), 5 (MAL), 7 (MEX)
- **4 habitat labels:** D (Degraded), H (Healthy), N (Early-stage restored <3 months), R (Mid-stage restored 32–53 months)
- **~542,187 WAV files** totalling **~9,036 recorded hours**
- **Audio format:** 1-minute WAV files at 16 kHz, ~1.83 MB each (from documentation; not independently verified)
- **No independent ecological measurements** present in the dataset
- **Key confounder:** Indonesia used 1-in-2 duty cycle vs 1-in-4 elsewhere
- **LOCO gaps:** Australia lacks N-class; Kenya and Maldives lack R-class

See `DATA_AUDIT.md` for the complete audit report.

## Known Limitations

1. Audio format properties (channels, bit depth, actual sample rate) have not been independently verified from file headers — only from documentation.
2. `ind_R1.zip` and `detections_indonesia.zip` have unverified MD5 checksums in the Figshare API.
3. Actual file timestamps, recording date distributions, and time-of-day coverage have not been inspected — requires archive content access.
4. `ken_H1` (1,060 files) and Indonesian H4, H5 sites have substantially fewer files than other sites; cause not confirmed.
5. No silent/corrupt recording check has been performed.

Phase 2 builds a reproducible manifest and stratified temporal sampling pipeline across all 45 sites and 5 countries.

- **Sampled Recordings Manifest:** [`data/sampling/sampled_recordings.csv`](file:///Users/saikarthik/coral-reef/EcoSound-Audit/data/sampling/sampled_recordings.csv) (120 pilot recordings)
- **Pipeline Summary:** [`reports/sampling_summary.json`](file:///Users/saikarthik/coral-reef/EcoSound-Audit/reports/sampling_summary.json)
- **Pipeline Log:** [`logs/sampling_pipeline.log`](file:///Users/saikarthik/coral-reef/EcoSound-Audit/logs/sampling_pipeline.log)

### Split Architecture & Dataset Limitations

1. **Strict Site-Level Separation:** All 45 sites are assigned exclusively to `train` (25 sites), `val` (8 sites), or `test` (12 sites). Zero site overlap exists between splits (leakage-free).
2. **All-Site Split Coverage:** When all 45 sites are evaluated, all four classes (D, H, N, R) are represented in train, val, and test splits (D: 8/2/5, H: 8/3/5, N: 3/2/1, R: 6/1/1 sites).
3. **Pilot Evaluation Limitations (Explicitly Documented):**
   - The 120-recording pilot evaluates a 12-site representative sample (10 recordings per site).
   - In this pilot subset, the `test` split contains **only 2 sites** (`kenya_H1` and `maldives_D1`).
   - Consequently, the pilot test split **only contains classes D and H** (10 recordings each); classes **N and R are missing in the pilot test set**.
   - Train contains classes H (10), N (20), R (30) (D missing in pilot train sample).
   - Val contains classes D (10), H (10), N (20) (R missing in pilot val sample).
   - **Do not claim 4-class evaluability in the pilot test set.** Full 4-class evaluation requires sampling from the remaining 33 assigned sites in Phase 3.

### Indonesia Recording Duty Cycle Handling
- **Difference:** Indonesia recorded every 2 minutes (30 recordings/hour) while Australia, Kenya, Maldives, and Mexico recorded every 4 minutes (15 recordings/hour).
- **What `hourly_binning` Corrects:**
  - Enforces a fixed per-site target sample quota (e.g. 10 in pilot, 100 in full), preventing Indonesia's 21 sites from contributing double the audio volume compared to equal-site allocations.
  - Stratifies selections across diurnal hours (0–23) and available deployment dates within each site, preventing temporal clustering within the deployment window.
- **What `hourly_binning` Does NOT Correct:**
  - It does **not** alter the internal duty cycle of individual recordings: Indonesia audio files were recorded at 2-minute cadence during their original deployment, whereas other countries were recorded at 4-minute cadence. Consecutive recordings in Indonesia remain closer in time than in other countries.
  - It does **not** normalize macro-seasonal variation: sites were deployed at different times across the 20-month project period (typically ~1 month per site).
  - Optional `subsample_50pct` mode is provided to explicitly filter Indonesia files to a 4-minute grid (`minute % 4 == 0`) prior to sampling if consecutive-interval parity is required.

### 2D Temporal Sampling (Date & Hour)
Sampling operates over a 2D grid of `(date, hour)` combinations within each site:
- Spreads selections across available deployment dates and diurnal hours with seed-dependent offsets to avoid clustered burst sampling.
- Verified in tests to span at least 4 distinct deployment dates (where available in deployment) and at least 8 distinct hours of the day per site in the 10-sample pilot.
